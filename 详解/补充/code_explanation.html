Java简易俄罗斯方块 - 项目代码详解

1. 项目概述

这是一个使用Java Swing库实现的经典俄罗斯方块游戏。它具备了游戏的核心功能，包括方块的随机生成、下落、移动、旋转、行消除、计分、游戏速度提升等。此外，项目还实现了以下高级功能：

  • 游戏开始倒计时： 在新游戏开始前有5秒倒计时，提升用户体验。
  • 下一个方块预览： 玩家可以看到下一个将要出现的方块，便于提前规划。
  • 游戏暂停/继续： 玩家可以随时暂停和恢复游戏。
  • 游戏存档/读档： 可以将当前游戏进度保存到文件，并在之后加载回来。
  • 排行榜系统： 游戏结束后，如果分数足够高，玩家可以留下姓名，计入本地排行榜。

2. 项目结构

项目遵循了良好的面向对象设计原则，将不同的功能模块划分到不同的类中。下图展示了核心类之间的关系：

主要文件及其职责如下：

  • Main.java: 主程序入口。负责在Swing的事件分发线程中创建并启动游戏主窗口，是整个应用的起点。
  • TetrisGame.java: 游戏主窗口 (JFrame)。作为顶层容器，负责整合所有UI组件，包括游戏面板、信息面板和状态栏。它还管理菜单栏事件，并处理保存、加载、游戏结束等高级逻辑。
  • TetrisPanel.java: 核心游戏面板 (JPanel)。这是游戏最核心的部分，处理所有游戏逻辑的实现，包括游戏循环、绘制棋盘和方块、响应键盘输入、碰撞检测、消行计分等。
  • NextBlockPanel.java: “下一个方块”预览面板。一个简单的UI组件，用于显示下一个即将下落的方块。
  • Block.java: 方块模型。定义了单个俄罗斯方块的数据结构，包括其形状（二维数组）、颜色以及旋转行为。
  • GameData.java: 游戏存档数据类。一个可序列化的数据容器，封装了保存一局游戏所需的所有状态（如棋盘布局、当前分数、当前方块等）。
  • HighScoreManager.java: 排行榜管理器。负责处理排行榜的逻辑，包括从文本文件 (tetris_leaderboard.txt) 读取、添加新纪录、排序和保存排行榜数据。
  • HighScoreEntry.java: 排行榜条目。代表排行榜中的一个条目，包含玩家姓名和分数。

3. 核心类详解

Main.java - 游戏启动入口

此类非常简单，其唯一的作用是确保Swing应用的线程安全。它使用 SwingUtilities.invokeLater() 来实例化 TetrisGame 对象，这保证了所有UI相关的操作都在事件分发线程（EDT）中执行，是Swing编程的最佳实践。

TetrisGame.java - 游戏主窗口

这个类是整个应用的“骨架”。它继承自 JFrame，并使用 BorderLayout 布局来组织界面：

  • CENTER: 放置 TetrisPanel，是游戏的主要操作区域。
  • EAST: 放置一个包含“下一个方块”预览 (NextBlockPanel) 和排行榜 (JTextArea) 的侧边栏。
  • SOUTH: 放置一个 JLabel 作为状态栏，显示游戏信息（如“游戏进行中”、“已暂停”等）。
  • 菜单栏 (JMenuBar): 提供“新游戏”、“保存/加载”、“暂停”、“退出”等操作的入口。

它还扮演着“协调者”的角色，例如当 TetrisPanel 中游戏结束时，会调用 TetrisGame 的 showGameOver() 方法来弹出统一的结束对话框。

TetrisPanel.java - 核心游戏面板

这是项目中最复杂的类，是游戏的大脑和心脏。

  • 游戏循环: 使用 javax.swing.Timer 来定时触发方块下落事件。Timer的延时（即 speed 变量）会根据分数动态调整，实现游戏加速。
  • 渲染: 重写 paintComponent(Graphics g) 方法来绘制所有视觉元素，包括棋盘网格、已固定的方块、正在下落的方块以及各种覆盖层（如倒计时、欢迎界面）。
  • 事件处理: 实现 KeyListener 接口来捕捉键盘事件。通过 keyPressed 方法处理左、右、下、空格（瞬移）和上（旋转）按键，改变方块的状态。
  • 核心逻辑方法:
    • spawnBlock(): 在顶部生成一个新的方块。
    • canMove(): 关键的碰撞检测算法，判断方块是否能移动到目标位置（检查边界和已固定方块）。
    • mergeBlock(): 当方块触底或碰到其他方块时，将其“合并”到棋盘的二维数组中。
    • clearLines(): 检查并消除所有填满的行，然后更新分数和游戏速度。
  • 状态管理: 维护 running, paused, gameOver 等布尔标志来控制游戏流程。

Block.java - 方块模型

这个类定义了俄罗斯方块的基本单元。

  • 形状 (shape): 使用一个二维整型数组 (int[][]) 来表示方块的形状。数组中的非零值代表方块的实体部分。
  • 颜色 (colorIndex): 一个整型值，对应 TetrisPanel 中定义的颜色数组索引。
  • 静态工厂方法: randomBlock() 方法可以随机从预定义的7种形状（I, J, L, O, S, T, Z）中选择一个，并返回一个新的 Block 实例。
  • 旋转: rotate() 方法实现了顺时针90度的旋转算法，通过创建一个新的二维数组并交换行列索引来完成。

GameData.java & 数据持久化 (序列化详解)

为了实现存档和读档功能，项目需要一种机制来将游戏内存中的状态（对象）保存到文件中，并在需要时恢复。Java的序列化 (Serialization) 机制完美地满足了这一需求。

什么是序列化？

序列化是指将Java对象转换为字节流（a stream of bytes）的过程。这个字节流可以被轻松地存储在文件中、通过网络传输或存入数据库。反过来，从字节流中重建出原始Java对象的过程称为反序列化 (Deserialization)。

项目中的应用

  1. 标记需要序列化的类:

    为了让一个类的对象能够被序列化，该类必须实现 java.io.Serializable 接口。这是一个“标记接口”，本身没有任何方法，只是“通知”JVM该类的对象是可以被序列化的。

    在本项目中，GameData 类和 Block 类都实现了 Serializable 接口。GameData 是存档的核心数据容器，而 Block 作为 GameData 的一个字段，也必须是可序列化的，否则会导致 GameData 序列化失败。

  2. 执行序列化（保存游戏）:

    在 TetrisGame.java 的 saveGame() 方法中： 

    try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("tetris_save.dat"))) {
    out.writeObject(tetrisPanel.getGameData());
    showStatus("游戏已保存");
}

    这里，ObjectOutputStream 扮演了关键角色。它接收一个 GameData 对象，并将其递归地转换为字节流，然后通过 FileOutputStream 写入到二进制文件 tetris_save.dat 中。

  3. 执行反序列化（加载游戏）:

    在 loadGame() 方法中： 

    try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("tetris_save.dat"))) {
    GameData data = (GameData) in.readObject();
    tetrisPanel.loadGameData(data);
    showStatus("游戏已加载");
}

    ObjectInputStream 则负责从 .dat 文件中读取字节流，并将其重新组装成一个 GameData 对象。注意，readObject() 方法返回的是一个 Object 类型，因此需要强制类型转换为 GameData。

序列化 vs. 纯文本

与 HighScoreManager 使用纯文本文件 (.txt) 保存排行榜相比，序列化有其独特的优缺点：

  • 优点:
    • 方便快捷: 无需手动解析和格式化数据，可以直接读写复杂对象及其完整的关系图。
    • 保留类型信息: 序列化后的数据保留了对象的类型信息，反序列化后能得到完全一致的对象。
  • 缺点:
    • 非人类可读: 生成的 .dat 文件是二进制格式，无法直接用文本编辑器查看和修改。
    • 版本兼容性问题: 如果类的结构（如增删字段）发生变化，直接用旧的序列化数据反序列化可能会失败（可以通过 serialVersionUID 进行更精细的控制，但本项目未涉及）。

4. 游戏流程分析

  1. 启动: Main -> TetrisGame 被创建，UI初始化完成，显示欢迎界面。
  2. 新游戏: 用户点击 "新游戏" 菜单，调用 tetrisPanel.startNewGame()。
  3. 倒计时: TetrisPanel 启动一个1秒的倒计时器，在状态栏更新倒计时秒数。
  4. 游戏开始: 倒计时结束，主游戏循环 Timer 启动。spawnBlock() 生成第一个方块。
  5. 游戏循环:
    • Timer 每隔 speed 毫秒触发一次 actionPerformed。
    • 调用 handleGameTick()，尝试将方块下移一格 (curRow++)。
    • 如果 canMove() 返回false（即方块无法再下落），则调用 mergeBlock() 将其固定在棋盘上。
    • 调用 clearLines() 检查消行、更新分数和速度。
    • 调用 spawnBlock() 生成下一个方块。如果新方块生成时就无法放置（触顶），则游戏结束。
    • 调用 repaint() 刷新屏幕。
  6. 玩家输入: 玩家按键，keyPressed 方法被触发，改变方块的列坐标 (curCol) 或形状 (调用 rotate())，然后立即调用 repaint()。
  7. 游戏结束: spawnBlock() 检测到触顶，设置 gameOver = true，停止计时器，并调用 parent.showGameOver()。TetrisGame 弹出对话框，处理排行榜记录，并等待玩家选择重新开始或退出。

5. 如何编译和运行

本项目使用 Apache Maven 进行构建。请确保您的系统中已安装Maven和Java Development Kit (JDK 21或更高版本)。

步骤 1: 编译和打包

打开命令行或终端，进入项目的根目录 (包含 pom.xml 文件的 javaeasytetris 目录)，然后执行以下Maven命令：

mvn clean package

该命令会完成以下工作：

  • clean: 清理之前构建生成的文件。
  • package: 编译所有Java源代码，并根据 pom.xml 的配置，将项目打包成一个可执行的 JAR 文件。

命令成功执行后，您会在 target 目录下找到一个名为 javaeasytetris-1.0-SNAPSHOT-jar-with-dependencies.jar 的文件。

步骤 2: 运行游戏

继续在终端中，使用以下 java 命令来运行打包好的JAR文件：

java -jar target/javaeasytetris-1.0-SNAPSHOT-jar-with-dependencies.jar

执行后，游戏窗口便会启动。

6. 总结

这个Java俄罗斯方块项目虽然规模不大，但它全面地展示了使用Swing进行桌面GUI应用开发的核心技术和最佳实践。通过模块化的类设计，项目将UI、游戏逻辑和数据管理清晰地分离开来，提高了代码的可读性和可维护性。

项目中对Java序列化和文本文件IO的综合运用，为数据持久化提供了两种不同场景下的解决方案。而通过Maven进行的标准化项目管理，则保证了项目构建和部署的便捷性。

总的来说，这是一个非常适合Java初学者和中级开发者学习和实践的案例，涵盖了从基础语法到面向对象设计，再到GUI编程和项目构建的完整流程。
